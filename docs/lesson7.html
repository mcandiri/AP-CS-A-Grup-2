Escape Sequences & null

The backslash

A String starts at a " and ends at the next ". So how do you put a quote mark inside a String? Or a new line, which you cannot type between quotes at all? Java's answer is one character, drawn at the top of the file: the backslash, \.

Inside a String, a backslash means “the next character is special”. The two together are called an escape sequence. The file lists the four you need:

You typeJava storesOn the console
\na new linethe rest goes on the next line
\ta tabjumps to the next tab column
\"a quote mark"
\\one backslash\

Notice the direction: \ is a backslash, the one above Enter on most keyboards. / is a normal slash — the one in // comments — and it has no special meaning inside a String.

\n · new line

Four lines from one println
System.out.println("W\nelcome\nto my\nworld!");
Console
W
elcome
to my
world!

One println, four lines. Every \n breaks the line exactly where it stands — even in the middle of a word, which is why W sits alone on the first line. Here is what Java actually keeps in memory; a new line is drawn as ↵:

"W\nelcome\nto my\nworld!" · 21 characters — each \n is one ↵ box

\t · tab

Three tabs — but count them carefully
System.out.println("Welc\tome \to my wo\trld!");
Console
Welc	ome 	o my wo	rld!

A tab does not add a fixed number of spaces. It jumps forward to the next tab column — on the console, every 8 characters. "Welc" is 4 characters, so the tab fills 4 spaces; "ome " then starts at column 8.

Watch out

Look at \to in the middle. It reads like the word “to”, but Java reads left to right: a backslash, then t — that is a tab. Only the o is left over. The console shows ome, a gap, then o my. The word “to” is gone.

\" and \\

Quote marks inside a String
System.out.println("Welcome \"to\" my wo\"rld");
Console
Welcome "to" my wo"rld

\" is a quote mark that does not end the String. Without the backslash, the " before to would close the String and the rest of the line would be nonsense to Java.

And if a backslash means “something special follows”, how do you print a backslash itself? Escape it: \\.

Backslashes
System.out.println("Welco\\me \\to my wo\\\\\\rld!");
Console
Welco\me \to my wo\\\rld!

Take the pieces left to right, two characters at a time:

  • \\me → \me. Two backslashes in the code, one on the console.
  • \\to → \to. Compare with the line above: there \to became a tab. Here the first backslash has already “used up” the second, so the t is just a t.
  • \\\\\\rld — six backslashes → three on the console: \\\rld.

The comment in the file shows where you meet this in practice — a Windows folder path:

A path with backslashes
System.out.println("D:\\Program Files\\");
Console
D:\Program Files\

One escape, one character

The backslash is something you type; it is not something Java stores. Each escape sequence becomes a single character, so it counts as one in length() and takes one index:

Escapes and length()
System.out.println("a\tb".length());
System.out.println("say \"hi\"".length());
Console

8

"say \"hi\"" · 8 characters · no backslashes stored

When it will not compile


        
Only certain letters may follow a backslash. Anything else is a compile error — and so is a quote mark you forgot to escape:


        

          
\d is not an escape

          
System.out.println("C:\data");

          
Compiler
error: illegal escape character

        


        

          
A quote that ends the String too early

          
System.out.println("say "hi"");

          
Compiler
error: ')' or ',' expected
error: ';' expected

        


        

          
The path, written with single backslashes

          
System.out.println("D:\Program Files\");

          
Compiler
error: illegal escape character
error: unclosed string literal

        


        
The last one has two problems. \P is not an escape. And the final \" is one — an escaped quote mark — so the String never gets its closing quote.


        

          Rule
          
A backslash in a String is always followed by one of n, t, " or \. If you want a backslash on the screen, type two.

        


        
The empty String


        
The second half of the file is about nothing — and there are two kinds of it. The first one we met in Lesson 6: two quote marks with nothing between them.


        

          
A String with zero letters

          
String a = ""; // empty string length = 0

System.out.println(a.length());
System.out.println(a.indexOf("dsa"));

"" is a real String. It just has no characters. You can call every method on it: its length is 0, and searching it for anything finds nothing, so indexOf answers −1. No crash.

Checking for null


        
Before you call a method on a String that might be null, ask first. The question is asked with == and !=:


        

          
Is there a String or not?

          
String a = "";
String b = null;

if (b == null) {
    System.out.println("b is null");
}
if (a != null) {
    System.out.println("a is a String, length " + a.length());
}
System.out.println(a == null);

          
Console
b is null
a is a String, length 0
false

        


        
a is empty, but it is not null — there is a String there, so a == null is false.


        
Why not equals? Because equals is a method, and calling a method on null is exactly what crashes:


        

          
Asking null with equals

          
String b = null;
System.out.println(b.equals(null));

          
Console
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.equals(Object)" because "b" is null

        


        
The program dies before equals can answer. == is not a method — it just looks at the variable — so it works even when there is no String.


        

          Rule
          
Two different questions, two different tools. Same letters? → equals, never == (Lesson 6). Is it null? → == null or != null, never equals. null is the only thing you compare a String to with ==.

        


        

          Watch out
          
When you build a String with += in a loop, start from "", never from null. Every method in Part 26 starts with String result = ""; for exactly this reason.

          Part 26 · Lesson26.java
          
Problem Solving with Strings

        


        
No new Java in this part. Everything below uses things you already know — length, indexOf, substring, equals, loops, if, Math.random and methods. What is new is putting them together to solve a problem nobody has solved for you.


        
How to attack a problem


        
Every problem in the file was solved the same way in class. Use the same four steps on the homework and on the exam:


        
    
          
  1. Say it in words. What goes in? What comes out? Write the method header first: name, parameters, return type.
    2. 
          
  2. Do one example by hand. With paper and a small input. If you cannot do it by hand, you cannot tell the computer how.
    3. 
          
  3. Find the small step that repeats. Almost always: “look at one letter” → substring(i, i + 1) inside a loop.
    4. 
          
  4. Test with answers you already know. Before you trust a method, call it with inputs where you know the right answer — the file does this with four passwords.
    5. 
        


        
For each problem below: read the problem, close your eyes to the code, and try steps 1 and 2 yourself first.


        
        
Problem 1 · A random word


        

          Problem
          
Write a method that takes a String of letters and a length, and returns a random “word” of that length, built from those letters. randomWord("abc", 4) could give "cabb", "aaaa", "bcab"…

        


        
Step 1 — the header. Two inputs, a String and an int. One output, a String:

        
public static String randomWord(String word, int length)


        
Step 2 — by hand. To pick one random letter of "abcdefghijklmnopqrstuvwxyz", you would pick a random index from 0 to 25, then take the letter at that index:


        
rnd = 3 → substring(3, 4) → "d"


        
Step 3 — what repeats. “Pick a random letter and add it to the result”, length times. The random index is Lesson 5's formula for a whole number in a range — here the range is [0, word.length()):


        

          
randomWord

          
public static String randomWord(String word, int length) {
    String result = "";

    for (int i = 0; i < length; i++) {
        int rnd = (int)(Math.random() * word.length());
        result += word.substring(rnd, rnd + 1);
    }
    return result;
}

        


        
    
          
  • Math.random() * word.length() is a double from 0.0 up to, not including, 26.0. The cast cuts it down to a whole number 0 to 25 — exactly the valid indexes.
    • 
          
  • substring(rnd, rnd + 1) is one letter. Even when rnd is 25, rnd + 1 is 26 — the length — and an end of length() is allowed. It never crashes.
    • 
          
  • result += … starts from "", the empty String of Part 25.
    • 
        


        
Step 4 — test it.


        

          
Six random words — one run; yours will differ

          
String alphabet = "abcdefghijklmnopqrstuvwxyz";
for (int i = 0; i < 6; i++)
    System.out.println(randomWord(alphabet, 5));

          
Console

cozca

ygnyj

        


        
Letters can repeat — cozca has two cs — because every pass picks from the whole alphabet again.


        

          Watch out
          
Every letter you want must be in the String you pass in. Count them: the alphabet has 26 letters. If one is missing — say i — then randomWord can never produce it, and nothing that needs an i will ever come out.

          
And do not write word.length() - 1 in the formula “to be safe”. That gives 0 to 24: the last letter, z, is never picked. In a million tries we got index 25 zero times.

        


        
        
Problem 2 · Guessing “door”


        

          Problem
          
Let the computer make random 4-letter words until it hits "door". How many tries does it need?

        


        
We do not need a new method — Problem 1 already makes random words. That is the reward for writing methods: the next problem is three lines.


        

          
Keep guessing — five runs; yours will differ

          
String word = "door";
String result = randomWord(alphabet, 4);
int count = 0;

while (!word.equals(result)) {
    result = randomWord(alphabet, 4);
    count++;
}
System.out.println(count);

          
Console
408080
561562
904507
258983
85509

        


        
Read the loop condition aloud: “while the word is not equal to the guess”. The ! from Lesson 1 turns equals around.


        
Why hundreds of thousands? Each letter has 26 choices, so there are 26 × 26 × 26 × 26 = 456,976 different 4-letter words, and only one of them is "door". On average it takes about that many tries — just like Lesson 5's dice, the runs scatter around the average.


        

          Watch out
          
In class the loop also printed every guess. That is fine for watching — but printing half a million lines is slow. When you only want the count, take the println out of the loop.

        


        

          Rule
          
The condition is !word.equals(result), not word != result. Lesson 6 said it: == and != do not compare letters. With != the loop never stops — we let it run 100,000 tries, it produced the right letters 151 times, and != still said “different” every time.

        


        

          In real life
          
This is why short passwords are dangerous. A program that guesses millions of times a second gets through every 4-letter word in under a second. Each extra character multiplies the work — by 26 for small letters only, by 60 for the characters in Problem 4.

        


        
        
Problem 3 · Is the password valid?


        

          Problem
          
A password is valid when all of these are true:

          
    
            
  • it has 6 to 12 characters;
    • 
            
  • it has at least one capital letter, one small letter, and one symbol from !@#$%^&*;
    • 
            
  • it has nothing else — no digits, no spaces, no other symbols.
    • 
          

          
Write isValid(String password).

        


        
Step 1. In: a String. Out: yes or no — a boolean.


        
Step 2 — the hard question. How does Java know whether a letter is a capital? We have no method for that. But we do have indexOf. Write all the capitals in one String and ask whether the letter is in it:


        
upper.indexOf("B") → 1 · found, so "B" is a capital

        
symbols.indexOf("%") → 4 · found, so "%" is a symbol


        
upper.indexOf("b") is −1: a small b is not in the capitals. So indexOf(ch) != -1 means “ch belongs to this group”. This is the trick of the whole problem.


        
Step 3 — what repeats. Look at one character, decide its group, count it. Then, after the loop, check the counts.


        

          
isValid

          
public static boolean isValid(String password) {
    String upper = "ABCDEFGHIJKLMNOPQRSTUVWXYZ";
    String lower = "abcdefghijklmnopqrstuvwxyz";
    String symbols = "!@#$%^&*";
    int minLength = 6;
    int maxLength = 12;

    if (password.length() < minLength || password.length() > maxLength) {
        return false;
    }

    int countUpper = 0;
    int countLower = 0;
    int countSymbol = 0;
    for (int i = 0; i < password.length(); i++) {
        String ch = password.substring(i, i + 1);
        if (upper.indexOf(ch) != -1) {
            countUpper++;
        }
        if (lower.indexOf(ch) != -1) {
            countLower++;
        }
        if (symbols.indexOf(ch) != -1) {
            countSymbol++;
        }
    }

    if (countUpper > 0 && countLower > 0 && countSymbol > 0
            && (countUpper + countLower + countSymbol) == password.length()) {
        return true;
    }
    return false;
}

        


        
    
          
  • The length check comes first, with an early return false. If it fails there is no point counting anything.
    • 
          
  • Three separate ifs, not else if — each character is tested against every group. (A character can only be in one of them, so else if would also work.)
    • 
          
  • The last line of the condition is the clever part. Every character that is a capital, a small letter or a symbol was counted once. If the three counts add up to the whole length, nothing else is in the password. A digit, a space or a ? is counted nowhere — and the sum comes up short.
    •

Problem 4 · Make a valid password


        

          Problem
          
Write generatePassword(): it returns a random password that isValid accepts.

        


        
The tempting plan is to build a valid password carefully: one capital here, one symbol there… The file does something much simpler. We already have a method that makes random text and a method that checks a password. So: make one, check it, and if it is not valid, make another. This is called generate and test.


        

          
generatePassword

          
public static String generatePassword() {
    String upper = "ABCDEFGHIJKLMNOPQRSTUVWXYZ";
    String lower = "abcdefghijklmnopqrstuvwxyz";
    String symbols = "!@#$%^&*";
    int minLength = 6;
    int maxLength = 12;
    String all = upper + lower + symbols;
    int length = (int)(Math.random() * (maxLength - minLength + 1) + minLength);
    String password = "";

    while (!isValid(password)) {
        password = "";
        for (int i = 0; i < length; i++) {
            int rnd = (int)(Math.random() * all.length());
            password += all.substring(rnd, rnd + 1);
        }
    }
    return password;
}

        


        
    
          
  • all glues the three groups into one String of 26 + 26 + 8 = 60 characters. Picking from all can give a character from any group.
    • 
          
  • The length is Lesson 5's range formula: (int)(Math.random() * (max - min + 1) + min) gives a whole number from 6 to 12 — both ends included, because of the + 1.
    • 
          
  • The loop starts with password = "", and isValid("") is false — too short. So the loop always runs at least once. Using the empty String as a “not yet” value is a neat trick.
    • 
          
  • The inner for is Problem 1's randomWord again. (You could write password = randomWord(all, length); instead — try it.)
    • 
        


        

          
Six passwords — one run; yours will differ

          
for (int i = 0; i < 6; i++)
    System.out.println(generatePassword());

          
Console
^YnUjYHXqN

How often does a random try fail? We counted over 10,000 passwords: on average the loop ran 1.47 times. Most first tries are already valid; a short one with no symbol gets thrown away and made again.


        

          Watch out
          
Delete password = ""; inside the loop and the program never ends. If the first try fails, the next 8 characters are added on top of the old ones:

          
Console
pass 1: wSuadgLh (8)
pass 2: wSuadgLhkMEbkcKB (16)
pass 3: wSuadgLhkMEbkcKBLqVjeWvw (24)

          
After pass 2 the password is longer than 12, so isValid can never say true again. When you repeat something in a loop, ask: what must be reset at the start of every pass?

        


        

          In real life
          
The “suggest a strong password” button in Chrome or on your phone does this job. The rules are the same kind as ours — a length range, character groups that must appear — and checking a sign-up form is isValid, run on every key you press.

    Suppose we delete the last check, (countUpper + countLower + countSymbol) == password.length(). Give a password that is now wrongly accepted.

Scramble a word


        

          Problem
          
Mix up the letters of a word, the way a word game does: "computer" → "tpeocmur". Every letter must be used exactly once.

        


        
randomWord(word, word.length()) is not enough — it can pick the same letter twice and skip another. The fix: after picking a letter, cut it out of the letters that are left, with two substrings glued around it.


        

          
Pick a letter, remove it, repeat — one run

          
public static String scramble(String word) {
    String left = word;
    String result = "";
    while (left.length() > 0) {
        int rnd = (int)(Math.random() * left.length());
        result += left.substring(rnd, rnd + 1);
        left = left.substring(0, rnd) + left.substring(rnd + 1);
    }
    return result;
}

for (int i = 0; i < 4; i++)
    System.out.println(scramble("computer"));

          
Console

tpeocmur
eocrmupt
omceputr

        


        
rnd = 3 · "com" + "uter" → left = "computer" without the p


        
left gets one letter shorter every pass, so the while runs exactly word.length() times and stops when nothing is left.


        
Hangman


        

          Problem
          
In Hangman the secret word is shown with blanks for the letters nobody has guessed yet. Write mask(secret, guessed): mask("door", "o") is "_oo_".

        


        
The same trick as isValid, turned around: there we asked whether a letter is in upper; here we ask whether it is in guessed.


        

          
Show a letter only if it was guessed

          
public static String mask(String secret, String guessed) {
    String shown = "";
    for (int i = 0; i < secret.length(); i++) {
        String ch = secret.substring(i, i + 1);
        if (guessed.indexOf(ch) != -1) {
            shown += ch;
        } else {
            shown += "_";
        }
    }
    return shown;
}

System.out.println(mask("door", "o"));
System.out.println(mask("door", "dr"));
System.out.println(mask("door", "dorx"));

          
Console
_oo_
d__r
door

        


        
When the mask equals the secret — mask(secret, guessed).equals(secret) — the player has won.


        
Caesar's secret code


        

          Problem
          
Julius Caesar hid his messages by moving every letter 3 places along the alphabet: a → d, b → e… and at the end it wraps around, x → a. Write caesar(text, shift). Anything that is not a small letter stays as it is.

        


        
A letter's position in the alphabet is alphabet.indexOf(ch). Add the shift, and use % 26 — Lesson 1's remainder — to wrap around past z:


        
"x" is at 23 · (23 + 3) % 26 = 0 → "a"


        

          
Shift every letter, wrap at z

          
public static String caesar(String text, int shift) {
    String alphabet = "abcdefghijklmnopqrstuvwxyz";
    String result = "";
    for (int i = 0; i < text.length(); i++) {
        String ch = text.substring(i, i + 1);
        int at = alphabet.indexOf(ch);
        if (at == -1) {
            result += ch;                 // not a small letter: keep it
        } else {
            int moved = (at + shift) % 26;
            result += alphabet.substring(moved, moved + 1);
        }
    }
    return result;
}

System.out.println(caesar("hello world", 3));
System.out.println(caesar("xyz", 3));
System.out.println(caesar("khoor zruog", 23));

          
Console
khoor zruog
abc
hello world

        


        
The last line decodes the message. Moving 23 more places is 3 + 23 = 26 — a full circle — so every letter is back where it started.


        
Why was it rejected?


        

          Problem
          
isValid only says false. A real sign-up form tells you why. Write whyInvalid(password) that returns the first broken rule as a message, or "OK".

        


        
Same counting loop as isValid. Only the end changes: instead of one big condition, one if per rule, each with its own return.


        

          
One rule, one message

          
public static String whyInvalid(String password) {
    String upper = "ABCDEFGHIJKLMNOPQRSTUVWXYZ";
    String lower = "abcdefghijklmnopqrstuvwxyz";
    String symbols = "!@#$%^&*";

    if (password.length() < 6) {
        return "too short";
    }
    if (password.length() > 12) {
        return "too long";
    }

    int countUpper = 0;
    int countLower = 0;
    int countSymbol = 0;
    for (int i = 0; i < password.length(); i++) {
        String ch = password.substring(i, i + 1);
        if (upper.indexOf(ch) != -1) {
            countUpper++;
        }
        if (lower.indexOf(ch) != -1) {
            countLower++;
        }
        if (symbols.indexOf(ch) != -1) {
            countSymbol++;
        }
    }

    if (countUpper == 0) {
        return "needs a capital letter";
    }
    if (countLower == 0) {
        return "needs a small letter";
    }
    if (countSymbol == 0) {
        return "needs a symbol";
    }
    if (countUpper + countLower + countSymbol != password.length()) {
        return "only letters and !@#$%^&* are allowed";
    }
    return "OK";
}

System.out.println(whyInvalid("abcdef"));
System.out.println(whyInvalid("aB%cdef"));
System.out.println(whyInvalid("aB%asSDASDDSADSADasdad"));
System.out.println(whyInvalid("aBB123?cdef"));
System.out.println(whyInvalid("aB%123"));

          
Console
needs a capital letter
OK
too long
needs a symbol
only letters and !@#$%^&* are allowed

        


        
The order of the ifs decides which message you see. "abcdef" breaks two rules — no capital, no symbol — but only the first one is reported.
