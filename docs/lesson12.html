Part 32 · Lessoon32.java

Arrays

In this lesson
  • Arrays: many values of one type under one name, in numbered boxes starting at 0.
  • Two ways to make an array, the default values Java puts in, reading and writing one box, and length.
  • Walking through an array with a for loop: printing, adding up, counting, going backwards, looking at neighbours.
  • The crash every array programmer meets: ArrayIndexOutOfBoundsException.

Why collections?

Imagine the exam scores of a class of 30. With what we know so far, that is 30 variables: int score1 = 72; int score2 = 85; … and so on, 30 lines. Now find the average: one very long line with 30 names. Now the highest score: 29 ifs. And next year the class has 32 students, so every line changes.

The problem is that the 30 scores are the same kind of thing, but the program treats them as 30 unrelated variables. What we want is one name for all of them, and a way to say “the 5th one”, or better, “the ith one”, so that a loop can visit them all. That is a data collection, and the first and simplest one in Java is the array.

What an array is

An array is a row of boxes, all of the same type, kept together under one name. Each box is called an element, and each has a number, its index. Here is the first array from the file:

int[] numbers = { 1,3,5,7,9, 11}; · values in the boxes, indexes underneath

Three facts about every array:

  • One type. An int[] holds only ints. There is no array with an int in one box and a String in the next.
  • Indexes start at 0. The first box is number 0, so the last box is number length − 1. Six elements: indexes 0 to 5. The same as the letters of a String in Lesson 6.
  • Fixed length. When the array is made, its number of boxes is fixed for ever. You can change what is in a box, but you cannot add a seventh box.
In real life

A pill organizer with seven boxes, one per day: one name (“my pills”), seven numbered boxes of the same kind, and you cannot add an eighth day. An array is exactly that, except that Java numbers the boxes from 0.

A new String[] is full of null, not of "". Printing a null box is fine, but calling a method on it, like s[0].length(), crashes with a NullPointerException, the same as with any null (Lesson 10).

Rule

name[i] is the element at index i. The first is name[0]; the element in position n (counting like a person) is at index n − 1.

Writing an element

An element is used exactly like a variable. You can put it on the left of =:

Only the box with that index changes; the others keep what they had. And everything that works with an int variable works with an int element: nums[1] += 3;, nums[2]++;, nums[3] = nums[0] * 2;.

length

Lessoon32.java
System.out.println(numbers.length);
System.out.println(nums.length);
Console
6
5

Every array knows how many boxes it has: name.length. Notice: no parentheses. For a String it was word.length(), a method. For an array it is numbers.length, a value stored in the array, like a public field you can read but not change.

Watch out

numbers.length() will not compile (cannot find symbol: method length()), and word.length without parentheses will not compile either. A memory trick: a String does something to count its letters (a method, with ()); an array simply has its length written on it.

Printing every element

Now the reason arrays exist. Because the index is just an int, it can be a variable: nums[i]. And a for loop can make i go 0, 1, 2, … through every index:

Lessoon32.java · the last lines
for(int i=0 ; i < nums.length ; i++) {
    System.out.print(nums[i] + " ");
}
Console
5 0 0 0 12
  • int i=0: start at the first index.
  • i < nums.length: stop before length. The last index is length − 1, so <, never <=.
  • i++: next box.
  • print, not println, with a space, so the values stand in one row.

This loop is the most important pattern of the whole topic. Every array program in this lesson is this loop with something different inside it. And because it says nums.length and not 5, it works for an array of any size without a change.

Rule

To visit every element: for (int i = 0; i < arr.length; i++), and use arr[i] inside. Write arr.length, never the number.

In short

An array is a fixed number of boxes of one type under one name. Make it with a list {…} or with new type[length], which fills it with 0, 0.0, false or null. arr[i] reads or writes box i; indexes go from 0 to arr.length − 1. length has no parentheses. A for loop from 0 while i < arr.length visits every box.

Printing, and [I@…

The first loop is the one from Part 32. Then a System.out.println(); with nothing in it, to end the row. The commented-out line shows what happens if you try to print the whole array at once:

Java does not print the values of an array for you. It prints a short code for the type and a label, a bit like Grup1.Height@66d3c617 in Lesson 11. [I is Java's short name for “array of int” ([ = array, I = int). A double[] prints [D@…, a String[] [Ljava.lang.String;@…. The number after @ changes from computer to computer.

Watch out

To see the values of an array, you must write the loop. println(numbers) never shows them.

Rule

Sum, count, average: each is “the traversal loop + an accumulator”. Reset the accumulator before the loop. Test and add arr[i], the value, not i, the position.

Backwards

Lesson33.java · reverse
for(int i=numbers.length-1  ; i >= 0 ; i--) {
    System.out.print(numbers[i] + " ");
}
Console
24 21 20 18 15 13 12 8 7 4 1

Every part of the loop is turned around: start at the last index, numbers.length-1 (10), keep going while i >= 0 so that index 0 is included, and step with i--. The array itself is not changed; we only visit it in the other order. It is the same idea as reversing a String's letters in Lesson 7.

ArrayIndexOutOfBoundsException

The file prints numbers.length, 11, and then has two lines commented out. If you take the // away from the first one:

Lesson33.java · numbers[11]

System.out.println(numbers[11]);

Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 11 out of bounds for length 11
	at Grup1.Lesson33.main(Lesson33.java:42)

The length is 11, so the indexes are 0 to 10. There is no box 11. Java does not guess and does not give back 0: it stops the program with an exception, and the message says exactly what went wrong: index 11, length 11. numbers[-3] gives the same exception with Index -3. The comment in the file is the whole rule: an index is wrong if it is < 0 or >= length.

The usual way to get this exception is not writing 11 by hand. It is one character in the loop:

<= instead of <

    System.out.print(n[i] + " ");

The first three rounds work and print; the fourth asks for n[3]. This kind of mistake, one step too far or one step too short, is so common it has a name: an off-by-one error.

Rule

Valid indexes: from 0 to length - 1. Anything < 0 or >= length throws ArrayIndexOutOfBoundsException. It compiles; it crashes when it runs.

Each line shows an element and the one just before it, numbers[i-1] and numbers[i]. Look carefully at the stop condition: i > 0, not i >= 0. When i is 0, i-1 would be −1, and we just saw what that does. So the loop stops at i = 1, which prints the first pair, 1 4. 11 elements give 10 pairs.

Watch out

Whenever you write arr[i-1] or arr[i+1], check the loop's first and last i. With i-1, i must never be 0. With i+1, i must stop at length - 2, that is i < arr.length - 1.

Why look at neighbours? Because many real questions are about change: did the temperature go up from yesterday? Is the list in order? Did a price rise? All of them compare arr[i-1] with arr[i]. The workshop has an example.

First and last

Lesson33.java · the comments
// arr[0] ---> first

// arr[length-1] --> last

Two formulas worth knowing by heart. The first element is always arr[0]; the last is always arr[arr.length - 1], whatever the size. arr[arr.length] is the classic wrong answer: one step past the end.

          In real life
          
Notice the cinema row: the ticket says seat 9, the program says taken[8]. Real programs convert all the time between “human numbers” starting at 1 and indexes starting at 0, and many real bugs, from wrong seats to wrong days, are off-by-one errors in exactly that conversion.

        


        

          In real life
          
A phone's photo gallery is a good picture of why length matters. The app never knows in advance how many photos you have. It loops i < photos.length, and the same code works for 12 photos or for 12,000.

        


        

          History
          
Not every language counts from 0. FORTRAN (1957) numbered arrays from 1, like people do. C (1972) chose 0, because an index there meant “how many boxes past the start”: the first box is 0 boxes past the start. Java took the habit from C. In 1982 the computer scientist Edsger Dijkstra wrote a famous short note, Why numbering should start at zero, arguing that ranges like “0 ≤ i < length” are the cleanest: the length is just the upper bound, and an empty array is 0 ≤ i < 0. That is exactly our loop condition.

The first loop is the 2019 StepTracker question from Lesson 9 again, now with the days in an array: a day is active at 10,000 steps or more, so 10000 counts and 9999 does not. In the second, each element is already a boolean, so it can be the condition itself: !present[i] is “was not here”.


        
Rising prices


        

          
Comparing neighbours

          
int[] price = {120, 125, 123, 130, 135, 131, 140};
int ups = 0;
for (int i = 1; i < price.length; i++) {
    if (price[i - 1] < price[i]) {
        ups++;
    }
}
System.out.println(ups);

          
Console
4

        


        
The neighbours idea from Lesson33, going forwards this time: the loop starts at i = 1 so that i - 1 is never −1. 120→125 up, 125→123 down, 123→130 up, 130→135 up, 135→131 down, 131→140 up: four days up. A stock app's “up 4 of the last 6 days” is this loop.


        

          In short
          
Average: sum, then divide by length, with a cast if the values are ints. Count: an if in the loop and a counter. Change from one day to the next: compare arr[i-1] and arr[i], starting at 1. Every one of them is the same traversal loop.
