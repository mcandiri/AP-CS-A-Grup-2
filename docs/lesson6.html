Part 21 · Lesson21.java

length & indexOf

The five methods

Java's String has dozens of methods. The AP exam uses five of them — the ones printed on the Java Quick Reference sheet you get in the exam room — and those five are exactly what this lesson covers. If a method is not in this table, you do not need it.

MethodGives backMeaningPart
word.length()inthow many characters21
word.indexOf(part)intwhere part first starts, or −121
word.substring(start, end)Stringthe characters from start up to, not including, end22
word.substring(start)Stringfrom start to the end22
word.equals(other)booleansame characters, in the same order?23
word.compareTo(other)intnegative, zero or positive: which comes first?24

Look at how they are called. Last week it was Math.abs(-3): the class name, a dot, the method. Now the String itself goes in front of the dot — word.length() means “the length of word”. The method works on whatever String is before the dot.

Every letter has a number

The comment at the top of the file draws it: the letters of "computer", and under each one its index. This drawing is the key to the whole lesson.

c o m p u t e r · 0 1 2 3 4 5 6 7
  • Counting starts at 0. c is at index 0, not 1.
  • The last index is length() - 1. Eight letters, indexes 0 to 7. There is no index 8.
  • Spaces are characters too. They get an index and they count in the length. On this page a space is drawn as ␣.

length()

The file does not quite use "computer". It uses "computere", with a second e on the end — and that extra letter matters later.

How many characters?
String word = "computere";
System.out.println(word.length());
Console
9
c o m p u t e r e

Nine letters, indexes 0 to 8. length() counts; it does not give the last index. Those two numbers are always one apart.

Watch out

The parentheses are part of the call: word.length(). Write word.length and the file will not compile — cannot find symbol · symbol: variable length. Java thinks you mean a variable called length, and there is none.

The first match wins

Here is why the file says "computere". There are now two es, at 6 and at 8. indexOf searches from the left and stops at the first one it finds:

Two e's, one answer
System.out.println(word.indexOf("e")); // 6
Console
6
search goes left to right and stops at 6 · the e at 8 is never reached

−1 means “not there”

Three misses
System.out.println(word.indexOf("C")); // -1
System.out.println(word.indexOf("x"));  // -1
System.out.println(word.indexOf("computers"));  // -1
Console
-1
-1
-1
  • "C" is not "c". Uppercase and lowercase are different characters. Every String method on this page is case-sensitive.
  • "x" is simply not in the word.
  • "computers" — every letter up to the s matches, but a piece is found only if all of it is there, in order, side by side.

Why −1? Because every number from 0 upward could be a real index. −1 can never be one, so it is safe to use as the signal for “not found”.

indexOf inside an if

The answer to indexOf is an int, so you can compare it. The file ends with two questions you can ask that way:

Two questions, asked with indexOf
String letter = "e";

if (word.indexOf(letter) == 0) {
    // word starts with letter
}

if (word.indexOf(letter) == -1) {
    // letter is not in word
}

And a third, commented out in the file: does the word end with the letter?

The commented-out check — try it on "computere"
String word = "computere";
String letter = "e";
System.out.println(word.indexOf(letter) == word.length() - 1);
Console
false

The word ends in e, and the check says false. word.length() - 1 is 8, the last index — but indexOf reported the first e, at 6. 6 is not 8. The idea only works when the letter appears once. That is why it is commented out; Part 23 fixes it.

In real life

Every Find box — Ctrl+F in a browser, the search in Word or WhatsApp — asks the same question as indexOf: where does this piece start, if it is there at all? A form that says “your password must be at least 8 characters” is checking length().

Cutting between letters


        
indexOf tells you where something is. substring takes a piece out. The comment in the file writes its rule the way a mathematician would: substring(int start, int end) takes [start, end) — the square bracket means start is included, the round one means end is not.


        
The easiest way to see this: stop numbering the letters and number the gaps between them instead. Gap 0 is before the c, gap 8 is after the r. substring(start, end) puts one knife at gap start, another at gap end, and gives you what is between the knives.


        
word.substring(2, 5) → "mpu" · knives at gaps 2 and 5


        
Two things fall out of the drawing at once:

        
    
          
  • The piece has end - start letters. 5 − 2 = 3: m, p, u.
    • 
          
  • A word of length 8 has gaps 0 to 8. So 8 is a fine end for a substring, even though there is no letter at index 8.
    •

First and last letter

          Rule
          
The letter at index i is word.substring(i, i + 1). That one pattern is how you reach any single letter with the methods on the exam sheet.

The empty String


        
What if both knives go in the same gap?


        

          
start equals end

System.out.println(word.substring(8, 8)); // ""

          
Console

No crash — none of the three rules is broken — and nothing between the knives. The result is the empty String "", a String with length 0. println prints it as an empty line, which is why the console shows three blank lines. Even substring(8, 8) is fine: gap 8 exists.


        
Backwards


        
Run the loop from the last index down to 0 and the letters come out in reverse. Only the loop header changes; the cut substring(i, i + 1) is the same.


        

          
From the last letter to the first

    System.out.println(word.substring(i, i + 1));
}

Start at word.length() - 1, the last index — not at word.length(). And keep going while i >= 0, so index 0 is included.


        
Pairs and triples


        
Make the cut two letters wide — substring(i, i + 2) — and the window slides along the word two letters at a time. The loop has to stop one pass earlier:


        

          
Every pair of neighbours

The last pair is "er", at i = 6: substring(6, 8). One more pass would be substring(7, 9) — gap 9 again. That is what the - 1 in the condition prevents. Three letters wide needs - 2:


        

          
Every three letters in a row

          Rule
          
A window w letters wide fits length - w + 1 times. Width 1: 8 windows. Width 2: 7. Width 3: 6. Too many passes crashes; too few silently misses the last window.

        


        
Here is what happens if you forget the - 1 for pairs. The first seven passes are fine; the eighth crashes:

The last line is a shorter way to get the last letter: substring(word.length() - 1) means “from the last index to the end”, which is one letter.


        
Splitting a full name


        
The file ends by putting indexOf and substring together. Find the space; everything before it is the first name, everything after it is the last name.


        

          
indexOf finds the knife, substring cuts

          
String fullName = "Ada Lovelace";
int index = fullName.indexOf(" ");
if (index != -1) {
    System.out.println(fullName.substring(0, index));
    System.out.println(fullName.substring(index + 1));
} else {
    System.out.println(fullName);
}

          
Console
Ada
Lovelace

        


        
index = 3 · substring(0, index) → "Ada" · the space is left out because end is not included

        
substring(index + 1) → "Lovelace" · + 1 steps over the space


        
    
          
  • substring(0, index) stops just before the space, because end is not included.
    • 
          
  • substring(index + 1) starts just after it. Without the + 1, the last name would begin with a space: " Lovelace".
    • 
          
  • The if handles a name with no space. For "Cher", index is −1, and substring(0, -1) would crash. The file checks first and prints the whole name instead.

equals & Counting

        


        
equals


        
equals asks one question: do these two Strings have the same characters, in the same order? The answer is a boolean.


        

          
equals(another string) → true / false

          
String x = "A";
String y = "B";
String z = "A";

System.out.println(x.equals(y));
System.out.println(x.equals(z));
System.out.println(z.equals(y));

          
Console
false
true
false

        


        
“Same” means exactly the same: "a" does not equal "A", and "cat" does not equal "cat " with a space on the end. Because it returns a boolean, equals goes straight into an if — and that is how the rest of the file uses it.


        

          Rule
          
To check whether two Strings are the same, use equals. Numbers are compared with ==; Strings are compared with .equals(...).

        


        
Never == for Strings


        
For ints, == asks “same number?”. For Strings it asks a different question: “is this the same String in memory?” Two Strings can hold exactly the same letters and still be two separate Strings — and then == says false. The worst part: sometimes it happens to say true, so the bug hides until it matters.


        

          
Sometimes == seems to work…

          
String a = "java";
String b = "java";
System.out.println(a == b);
System.out.println(a.equals(b));

          
Console
true
true

        


        
Two Strings typed directly in quotes with the same letters are shared by Java, so here a and b really are the same String. This is the example that makes people think == is fine. Now make the String with a method instead:


        

          
…until the String comes from substring

          
String word = "computer";
String part = word.substring(0, 4);
System.out.println(part);
System.out.println(part == "comp");
System.out.println(part.equals("comp"));

          
Console
comp
false
true

        


        
part prints as comp, and == still says false. substring built a new String; it has the right letters but it is not the "comp" in quotes.


        

          
…or from +

          
String first = "com";
String full = first + "puter";
System.out.println(full);
System.out.println(full == "computer");
System.out.println(full.equals("computer"));

          
Console
computer
false
true

String name = "Ada Lovelace";

And the most dangerous one — the counting loop below, with a single change. It compiles, it runs, there is no error message, and the answer is simply wrong:


        

          
Counting e's with == instead of equals

          
int count = 0;
String word = "the professor drinks a cup of coffee in the office";
for (int i = 0; i < word.length(); i++) {
    String c = word.substring(i, i + 1);
    if (c == "e") {        // wrong: should be c.equals("e")
        count++;
    }
}
System.out.println(count);

          
Console
0

        


        
There are six es. Every c is a new String made by substring, so c == "e" is false on every pass — even the six where c is "e".

          Rule

equals only says same or not the same. compareTo says which one comes first, the way words are ordered in a dictionary. It answers with an int, and the sign is what matters:

Longer words


        
For words of more than one letter, Java walks along both words together, index by index, and stops at the first position where they differ. Only those two letters are subtracted; everything after them is ignored.

          Rule
          
On the exam, only the sign of compareTo matters: negative, zero, positive. Use it as a.compareTo(b) < 0 (“a comes first”), never as a.compareTo(b) == -1 — the result is −2, −3, −32… as often as it is −1.

public static int countOf(String word, String part) {
    int count = 0;
    for (int i = 0; i <= word.length() - part.length(); i++) {
        if (word.substring(i, i + part.length()).equals(part)) {
            count++;
        }
    }
    return count;
}
